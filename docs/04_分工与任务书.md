## 3. 每人交付物

### A：组长、网络协议架构与抓包内核

- 课程知识：网络分层模型、以太网帧格式、IPv4/IPv6 首部、TCP/UDP 端口和抓包原理；
- 需求分析和总体技术方案；
- 组内进度表、任务书和最终提交材料清单；
- 网卡枚举、抓包线程、报文解析和会话管线；
- 模块接口约定、代码集成和代码审查；
- pcapng 导出、打包和最终可执行程序验收；
- 组织组内联调和答辩分工。

验收标准：程序能在组员电脑上启动、选择网卡、开始/停止抓包；抓到的 Ethernet、IPv4/IPv6、TCP/UDP 字段符合协议格式；能完成一次完整的保存与回读演示。

### B：协议字段语义与可视化

- 课程知识：MAC 地址、EtherType、ARP、ICMP、IP 版本、TTL/Hop Limit、协议号、TCP 标志和端口；
- 编写“协议字段—界面显示”对照表，明确 IPv4 的 TTL 与 IPv6 的 Hop Limit 等字段映射；
- 处理 ARP、ICMP、非 IP、VLAN、IP 分片等非 TCP/UDP 场景的显示规则；
- 主窗口布局和统一视觉样式；
- 报文列表表格模型与增量刷新；
- 字段详情树；
- 长度折线图、长度分段柱状图、IPv4/IPv6/其它数据柱状图；
- 运行状态、丢包、速率和资源信息展示；
- 界面截图和答辩演示操作流程。

验收标准：抓包过程中界面不阻塞；选择报文后能展开课程要求字段；字段值与协议定义一致；TCP 标志、VLAN、ARP/ICMP 和 IPv6 字段有明确的显示规则；三类图表能随数据刷新。

### C：流量测量与异常分析

- 课程知识：IP 分组长度、MTU、IP 分片、IPv4/IPv6 地址族、TCP/UDP 协议分布和常见流量异常；
- 明确长度统计按 IP 分组总长度计算，非 IP 数据单列；
- 长度、分桶、协议和传输层统计；
- IPv4/IPv6/其它数据分类；
- pcapng 分段写入、单文件导出和回读；
- 资源日志 CSV；
- 统计、持久化和资源日志相关单元测试；
- 统计口径说明和数据一致性检查；
- 可选实现 SYN 泛洪和 ICMP 回显异常的检测口径与提示。

验收标准：保存前后报文总数和三类统计一致；`46/47/1499/1500` 长度边界测试正确；非首片分组的端口显示为 `N/A`；异常检测阈值有文档说明；资源 CSV 字段完整。

### D：协议一致性测试与长稳

- 课程知识：ARP、ICMP、DNS、TCP 三次握手、UDP、IPv6、VLAN 和 IP 分片；
- 设计协议测试矩阵，明确每种协议要生成的流量、预期字段和预期统计；
- 使用 ping、DNS 查询、网页访问、TCP 连接和 IPv6 工具生成真实测试流量；
- 测试计划和测试用例清单；
- 使用真实网卡验证 MAC、EtherType、IP 地址、TTL/Hop Limit、协议号、端口和 TCP 标志；
- 回归测试、GUI 冒烟测试和异常场景检查；
- 24 小时连续运行、资源记录和结果整理；
- 测试记录、问题清单和修复跟踪；
- 答辩演示数据、截图、录屏素材和 PPT 初稿。

验收标准：提交可复现的协议测试矩阵；至少覆盖 ARP、IPv4/ICMP、TCP、UDP、IPv6 和 VLAN；字段值与实际协议行为一致；24 小时运行有开始/结束时间、资源 CSV、pcapng 和截图证据。

## 6. 协作规则

1. 每个模块的负责人对该模块的代码、测试和说明负责，接口变更必须提前在组内说明。
2. A 负责合并和最终验收，但不得绕过模块负责人直接覆盖其未完成的改动。
3. C 维护长度、MTU、协议分布和异常阈值等测量口径；任何统计定义变化必须同步更新测试和报告。
4. D 的每条测试记录必须写清协议、生成流量的方法、预期字段、实际结果和 pcapng 证据；问题修复后由 D 回归。
5. 报告中的分工、工作量和实际贡献保持一致，最终由全组确认。
6. 每次组会记录日期、完成项、阻塞项和下一步责任人，作为过程材料。
