## 2. 项目背景与目标

课程要求设计一个安装在个人电脑上的网络流量分析软件。软件抓取进出本机的报文，解析数据链路层、网络层和传输层的关键字段，实时展示统计数据，并支持原始数据的持久化和回读。软件还必须连续运行 1 天以上，记录运行时长和资源消耗情况。

本项目的基本目标是：

1. 在 Windows 上稳定抓取指定网卡的进出报文；
2. 正确解析课程要求的关键协议字段；
3. 以折线图和柱状图展示分组长度及协议类型统计；
4. 保存原始报文，并能在本软件中重新加载和展示；
5. 连续运行不少于 24 小时，保持界面可用、内存有界、数据可追溯；
6. 记录 CPU、内存、磁盘写入和丢包等指标，为报告中的资源消耗分析提供证据。

## 3. 用户与使用场景

### 3.1 主要用户

- 课程设计小组成员：运行软件、选择网卡、观察流量、保存和回读数据；
- 答辩教师：检查字段解析、统计图表、持久化、长时间运行记录和资源占用证据。

### 3.2 典型场景

1. 用户启动软件，选择 WLAN 或以太网网卡，点击开始；
2. 软件实时显示报文列表及链路层、网络层、传输层字段；
3. 用户切换统计页，观察长度分布、分段数量和 IPv4/IPv6/其它数据数量；
4. 用户保存当前会话，关闭软件后重新打开文件，恢复报文列表和统计结果；
5. 软件在目标电脑上连续运行 24 小时以上，定期写入资源日志；
6. 答辩时展示运行时长、资源曲线、抓包结果和网络访问测试。

## 4. 系统范围

### 4.1 范围内

- 本机单网卡或多网卡选择；
- 被动抓包，不修改、不转发、不注入报文；
- Ethernet、VLAN、IPv4、IPv6、TCP、UDP 和常见非 IP 数据；
- 课程要求字段的解析与展示；
- 长度统计、长度分桶统计、IPv4/IPv6/其它数据统计；
- pcapng 原始数据保存和回读；
- 运行时长、资源占用和丢包计数；
- 可选的基础异常流量提示。

### 4.2 范围外

- 报文内容解密、应用层协议还原和大规模入侵检测；
- 路由器、交换机等网络设备的配置；
- 分布式抓包、远程控制和云端上传；
- 对抓到的载荷进行业务分析；
- 完整替代 Wireshark 的所有协议解析功能。

## 6. 字段与数据口径

### 6.1 协议字段

| 层级 | 字段 | 处理规则 |
| --- | --- | --- |
| 数据链路层 | 源 MAC、目的 MAC | 从 Ethernet 头读取并格式化为 `aa:bb:cc:dd:ee:ff` |
| 数据链路层 | 以太网类型 | 显示十六进制值和名称，如 `0x0800 IPv4`、`0x86DD IPv6`、`0x0806 ARP` |
| 网络层 | 源 IP、目的 IP | IPv4/IPv6 均显示；非 IP 报文显示 `N/A` |
| 网络层 | IP 版本 | IPv4 显示 4，IPv6 显示 6，非 IP 显示 `N/A` |
| 网络层 | TTL | IPv4 读取 TTL；IPv6 显示对应的 Hop Limit，界面注明字段映射 |
| 网络层 | 协议号 | IPv4 读取 Protocol；IPv6 读取 Next Header；扩展头场景尽量解析最终传输层协议 |
| 传输层 | TCP/UDP 源/目的端口 | 仅 TCP/UDP 显示；非 TCP/UDP 显示 `N/A` |
| 传输层 | TCP 标志位 | 显示 SYN、ACK、FIN、RST 是否置位；UDP 和非 TCP 报文显示 `N/A` |

### 6.2 长度统计口径

原文的 `<=46`、`46-1500`、`1500` 存在边界重叠，项目采用以下明确口径：

- 长度定义为 **IP 分组总长度**：IPv4 使用 `IPv4.len`；IPv6 使用 `40 + IPv6.plen`（包含 IPv6 扩展头的总长）；
- 分桶为 `<=46`、`47-1499`、`>=1500`；
- 非 IP 数据（如 ARP）计入“其它数据”，不进入 IP 长度折线图和长度分桶图；
- 界面提示和报告必须明确写出上述口径，避免答辩时产生歧义。

### 6.3 协议分类口径

- IPv4：有效 EtherType 为 `0x0800`；
- IPv6：有效 EtherType 为 `0x86DD`；
- 其它：ARP、LLDP、未知 EtherType、VLAN 标签下无法识别为 IPv4/IPv6 的数据等；
- 带 802.1Q VLAN 标签时，应读取内层 EtherType 再分类。

### 6.4 异常与不完整报文

- 截断报文：尽可能展示已解析字段，缺失字段显示 `N/A`；
- 非首片 IP 分片：传输层端口可能不存在，显示 `N/A`；
- 非 TCP/UDP：仅展示网络层及以下字段；
- 解析异常必须被记录，不能让抓包线程或界面退出。

## 7. 数据持久化需求

1. 原始报文保存为 pcapng 文件，保留时间戳和原始字节；
2. 保存操作不能阻塞 GUI，应显示保存状态；
3. 打开 pcapng 后，应重建报文列表、字段详情和三类统计图；
4. 支持 24 小时运行时的分段写入，避免单个文件无限增长；
5. 提供“导出当前会话为单个 pcapng”的能力，满足“另存为一个文件”的要求；
6. 磁盘可用空间低于安全阈值时，停止原始数据写入但继续统计并提示用户；
7. 文件损坏或格式不支持时，给出明确错误信息，不覆盖原文件。

## 8. 非功能需求

| 编号 | 类别 | 要求 |

## 10. 约束、假设与风险

### 10.1 约束

- 只能抓取本机网卡可见的流量，无法看到交换网络中其他主机的全部流量；
- 无线网卡在监视模式、驱动和 Npcap 兼容性方面存在差异；
- 抓包能力依赖 Npcap，目标电脑必须安装驱动；
- 24 小时全量保存原始报文可能产生数十 GB 数据，必须设置分段和磁盘保护；
- Python 3.14 较新，打包工具和 Qt 插件需要通过实际构建验证。

### 10.2 假设

- 目标电脑为当前 Windows 11 电脑或同级别 Windows 电脑；
- 抓包使用当前已安装的 Npcap 1.10.4，服务正常运行；
- 用户允许程序读取网卡数据和写入选定目录；
- 答辩环境可安装或已安装 Npcap。

### 10.3 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 高流量导致队列积压 | 丢包、界面卡顿 | 有界队列、批量更新、记录丢弃计数、只保留最近报文 |
| 24 小时 pcapng 过大 | 磁盘耗尽 | 分段写入、磁盘阈值保护、默认只记录必要长度 |
| 非 IP/分片/IPv6 扩展头 | 字段缺失或误判 | 明确 `N/A` 规则，补充构造报文测试 |
| Npcap 权限问题 | 无法开始抓包 | 启动时检测并给出安装/权限提示 |
| PyInstaller 打包 Qt | 打包体积大或缺少插件 | 使用 one-dir、实际构建并做无 Python 环境启动测试 |
